## 共识范围

算法以 Castro/Liskov 的 [PBFT 正常路径、检查点与视图切换](https://static.usenix.org/publications/library/proceedings/osdi99/full_papers/castro/castro_html/node4.html) 为依据，固定 N=4、f=1。每个副本有独立私钥；配置提供全体公钥。跨运行消息通过 run ID 隔离。

一次新批次的路径为：主节点签名 PREPREPARE → 备份节点分别签名 PREPARE → 收到合法提案和两个不同备份的匹配 PREPARE 后进入 prepared → 广播 COMMIT → 收到三个不同副本的匹配 COMMIT 且本地 prepared 后 committed-local → 按序执行。副本的自身 COMMIT 可计入三个投票，主节点不发送 PREPARE。

客户端请求也使用 Ed25519。副本验签后才将请求加入池中；客户端验证回复，并等待两个不同副本的一致结果。客户端重复请求不重复执行，批次中重复的交易 ID 也由状态机去重。用相同请求 ID 发送不同内容会被拒绝；测试负载应使用新前缀。

视图切换携带稳定检查点证明和 prepared 证明。新主节点收集三个不同副本的 VIEW_CHANGE（包含自身），逐序号选择证明中视图最高的 prepared 值，缺口使用空批次；其他副本独立验证 NEW_VIEW 是否保留所有必须恢复的值。单个副本的视图请求不能迫使集群立即切换。等待时间在连续切换时退避。

检查点需要三个不同副本对相同状态摘要签名。获得稳定检查点后清理旧的共识消息；状态追赶验证检查点和后续提交证书。一次最多接受稳定检查点后 64 个序号，限制异常的大序号输入。为了方便第一阶段检查，检查点携带完整内存状态，尚未实现增量传输。

本阶段没有宣称完成生产级 PBFT 实现或穷尽所有 Byzantine 攻击验证。自动测试覆盖了明确列出的故障和恶意输入场景。进程重启恢复、持久化投票 WAL、成员变更、检查点流式传输等仍是后续工程范围。

## 延迟机制

每个副本有一个独立网络线程，维护按 `(due_time, serial)` 排序的消息队列，使用 `steady_clock` 计算预计发送时间。消息入队后唤醒网络线程，线程使用 `poll` 等待最近到期任务或可读写 socket。连接、发送和接收都使用非阻塞 socket。

因此共识线程不会为链路延迟休眠，网络线程也不会阻塞等待某个失联节点。广播的每份消息分别计时，所有到期消息可在同一次调度中发起 TCP 发送。到期任务在连接数上限以内释放，繁忙时的额外排队会体现为 `release_ms - due_ms`。

每条应用消息目前使用一条短 TCP 连接，帧为 4 字节网络字节序长度 + UTF-8 JSON。会处理部分读写、连接失败和超时；最大帧 16 MiB、发送等待队列 100000 个任务。失败计入 `network_failures`，接收队列满计入 `inbox_dropped`；PBFT 和客户端负责超时重传。正式协议性能研究可在后续统一换成长连接，但所有方案应使用相同底层。

延迟只在发送端施加一次，同一副本的本地投票不走网络。跨片测试 PING/PONG 也经过相同队列，所以能验证真实配置效果。探测回复必须由预期目标身份签名。

## 执行与指标

叶子执行 `fib_iterations` 次迭代加法，结果参与状态摘要。每个 key 的新摘要依赖旧值/版本、交易及 Fibonacci 结果，因此可以检测相同交易顺序不同造成的分叉。所有执行均在确认共识提交之后发生。

协调者只维护有序交易记录，计入 `ordered_cst_transactions`；当前不向参与叶子发起完整跨片协议。客户端结果明确区分 executed 与 ordered_only。

客户端端到端时间只使用同一个客户端进程的单调时钟；分片对 RTT 只使用同一个源副本的单调时钟。不同机器不需要为这些指标同步墙钟。节点的累计执行量不相加为系统交易量；同一笔交易的四次副本执行只对应一次客户端确认。

指标文件每约 100 ms 刷新。客户端计数是确认数，稳态饱和吞吐需另行设计预热、负载扫描、统计窗口和排空策略。同步检查点可使落后副本一次跳到已验证的状态，此时应结合 `state_sync` 事件和链摘要检查逻辑历史，不能要求每个副本的物理日志文本逐字相同。

## 与旧代码的关系

旧框架把分片和节点合并为一个对象，网络端点也只有分片 ID。直接在 `runConsensus()` 内补几轮消息仍然无法获得独立副本状态。因此本阶段替换了活动的源码与入口。修改前的源码快照由历史标签 `stage1-pbft` 保存，当前工作区已移除旧源码目录。

对应旧问题的处理：

- 队列搬移加休眠的“共识”替换为真实投票与提交条件。
- 裸指针交易队列替换为拥有明确生命周期的值对象；旧共识日志按稳定检查点清理。
- 配置中根、叶子、分片数量统一从一棵树推导，不再混用不一致的旧文件。
- 负载由客户端按指定总数、速率和参与集合生成，交易 ID 有分隔符与运行前缀，NCA 由实际参与集合计算。
- 执行计数使用完整交易和唯一标识，不再采用整数 `+= 0.5`。
- 客户端记录完成时间，不使用执行前批次时间或多个分片错位窗口的求和。
- 删除固定的 100 ms 接收休眠和在执行线程中的串行网络等待。
- 启停使用实际 Popen PID 和运行目录身份核对，日志不覆盖，失败启动会清理已启动部分。

这些替换只覆盖第一阶段底座。旧代码尚未完成的跨片提交闭环没有伪装成“已修好并支持”：新入口明确将它留到下一阶段。
