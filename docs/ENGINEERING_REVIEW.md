# 工程实现审查与修复（2026-10-02）

检查覆盖 TCP 传输、跨片转发、请求去重、共识批大小和状态统计。本轮随后按用户更正简化跨片协议：上层一次排序 PBFT、两叶各一次 PBFT，上层收齐完成 QC 直接结束；以下说明已同步新路径。新代码的测试与性能以本轮实际输出为准，旧协议的通过记录不自动沿用。

## TCP 传输

现有传输已按目标地址复用 TCP 长连接，并支持长度头分段、消息体分段和同一连接中的多帧解析，不再为每条消息创建连接。空闲连接会在 30 秒后关闭，后续消息重新建立连接。

本轮修复了两个会影响长负载的问题：

- 发送缓存只限制任务数量时，任务移入连接缓存后可能继续无限积压。现在入队时统一预留待发送字节额度：所有目标合计最多 **128 MiB**，单个目标最多 **32 MiB**，同时保留任务数量上限。超过额度时 `send` 返回失败，释放已写字节和丢弃任务的额度。
- 原来追加消息会不断推迟超时，停止读数据的目标在持续负载下可能永远不被关闭。现在发送开始后，只有真正写入 socket 的进展才延长 **3 秒**发送超时。每轮最多释放 256 个到期任务，给其他连接保留 I/O 服务机会。

这些上限统计延迟队列和连接中的未写数据，不代表进程总内存上限；内核 TCP 缓存、接收缓存和应用收件队列另计。

`status.json` 中的网络字段：

| 字段 | 含义 |
| --- | --- |
| `network_buffered_bytes` | 延迟队列及连接中尚未写入 socket 的总字节数 |
| `network_active_connections` | 当前入站和出站连接总数，不包含监听 socket |
| `network_connect_attempts` | 累计主动调用 TCP `connect` 的次数 |
| `network_connections_reused` | 累计复用已有出站连接发送任务的次数 |
| `network_queue_errors` | 入队额度或连接资源限制导致的拒绝次数 |
| `network_timeout_errors` | 有待发数据的连接因无写进展而超时的次数 |

网络采用 best effort 语义：写入内核成功并不等于对方已处理。断线时清理未发送数据，下一次协议重试建立新连接。PBFT 和跨片流程依靠认证、超时重试、去重及检查点同步保证恢复；传输层不盲目重放可能已部分送达的数据。

## forward 聚合与跨片通信

每个分片的 forward 使用当前 PBFT primary，即 `view % 4`；视图切换时一起更换，切换期间暂停主动转发。

- `CST_ORDER` 携带协调分片的 PBFT 排序证书，由协调分片 forward 跨片发送。
- 叶子副本先在片内把 `CST_PREPARED` 发给本片 forward。forward 收齐 **3 个不同副本**的匹配签名后组成 QC，再发送给另一叶子片。
- 执行完成后，叶子副本把 `CST_ACK` 发给本片 forward。forward 同样收齐 **3 个不同副本**的匹配签名后转发 ACK QC 给协调片。
- 叶子本地 PBFT 提交后，在同一槽内等待依赖；依赖齐全才更新 KV、applied 和业务摘要，不再提 FINALIZE。
- 协调片核对两叶 QC 的订单/执行摘要和三签阈值后直接回复，不再运行 DECISION PBFT，也不下发 DONE。完成证明每个 forward view 主动发送一次后保留档案；根重发 ORDER 可触发叶子补发，根片内部 QUERY 补取同伴已有 QC。本片完成票/QC 尚缺时仍限频重试，不无限广播所有已完成 ACK。

源分片只有当前 forward 负责跨片发送。消息可以投递到目标分片的 4 个副本，以保留校验、同步和视图切换能力；目标验证证书后只由自己的 PBFT primary 发起提案，其他副本参与同一轮共识。接收 4 份消息不等于启动 4 次独立共识。

## 共识前去重与批处理

去重同时检查交易 ID 和交易内容摘要：

- 相同 ID、不同内容返回冲突，不能当作重试接受。
- 相同交易已经完成时，新请求直接获得 `duplicate` 结果，不再为纯重复交易发起共识。
- 不同请求包含仍在处理的相同交易时，后到请求等待原请求完成，避免并发重复提案。
- 原请求 ID 的重试返回其缓存结果。跨片请求需要等待真正完成后再返回完成结果。
- 一个已签名请求同时包含新旧交易时，保留完整请求及签名，新交易正常进入共识，旧交易不重复执行；不会通过修改交易列表破坏签名。

两个混合请求共享旧交易时分到不同批次，避免批内重复 ID 校验导致整批被拒；副本即使以不同顺序收到交易别名，也在提交后清理已完成的待处理请求。检查点同步后重新核对交易内容摘要，不能把同 ID 的不同交易错误答复为重复。

跨片组批依据连续请求的参与分片集合，默认上限为 `min(64, batch_size)`。负载生成器使用跨片上限选择默认请求大小，避免生成超限请求后一直等不到共识；显式超限请求获得明确错误。`--batch` 控制客户端每个请求的交易数，协调片可以把多个请求合入同一个跨片批次。

状态摘要按变化条目更新 Merkle treap，检查点保存并复用冻结摘要；远端快照仍完整重建验证。KV 摘要只在 KV 改变时按原格式重算，定期状态输出复用缓存。正常提交的去重索引只释放本批拥有者、唤醒关联等待者，完整重建仅用于检查点追赶。详见 [PERFORMANCE_OPTIMIZATION.md](PERFORMANCE_OPTIMIZATION.md)。

协调片的 `cst_orders` 只存确定性订单元数据；收到的任意三签子集和完成派生结果属于易失缓存，不参与 PBFT 摘要。检查点追赶后，副本用片内 `CST_RESULT_QUERY` / `CST_RESULT_PROOFS` 向其他根副本补取原 ORDER 证书和 ACK QC；若叶子需再发送证明，则重发 ORDER。验证订单摘要、双方一致执行摘要和完成证明后重建请求及交易结果缓存，不另开共识、不重复业务执行。

叶子临时准备记录不进入正式 state，依赖等待期间该槽 applied 不前移。完成后提交日志保存双方三签依赖的 `execution_witness`；SYNC 检查点后缀带对应 witness，使落后副本能在原 ORDER 槽重演执行。已提交快叶保留依赖档案，响应 `CST_DEPENDENCY_QUERY`，避免其先完成后慢叶永久缺读数据。

已 committed 的执行等待不单独计为 PBFT 超时，当前 view 同槽已有投票仍重发至执行完成，以帮助缺提交证书的副本。完整 commit 证明进入 VIEW_CHANGE；NEW_VIEW 验证并导入与恢复值一致的原提交证书，原槽直接继续执行等待。forward 自身追赶后若缺依赖档案，向本片广播 QUERY，备份可本片应答，仍由 forward 转发远片。根的混合批则在旧交易原完成缓存恢复前保持等待，恢复后复用原结果，避免旧交易结果摘要随新批次改变。

SYNC 同时可传已 committed 未 applied 的证书，接收者缺 witness 时只进入原槽等待，不提前更新 seq/KV/journal；请求者 after 与发送者 applied 相同也不能漏掉这类证据。NEW_VIEW 后持有者分享一次未执行提交证明，覆盖所选三个 VIEW_CHANGE 漏掉唯一完整证书的情况。根完成证明补取按 order index 数值排序，待补本片 ACK QC 用活动集合维护；健康根全部订单完成后不做历史扫描，避免空闲处理成本随历史增长。

## 当前边界

- 完整跨片执行和完成路径目前覆盖一个协调片、两个叶子片的拓扑；其他拓扑仍需后续阶段扩展。
- 一个分片永久失去共识能力时，尚无跨片 abort 协议，未完成交易会保持等待。
- 去重记录、历史状态和日志会随长期运行增长，尚未实现完整的历史裁剪策略。
- 尚未实现 WAL 驱动的同一运行节点重启恢复；当前代码禁止带既有提交日志直接重启节点，以避免丢失投票状态后重复投票。
