## 三轮结果

顺序为“旧→新、新→旧、旧→新”，每次都停止上一次集群后再启动下一次。业务批只统计协调者原始排序记录，不重复计入叶子的执行记录。

| 轮次 | 修改前 TPS | 修复后 TPS | 业务批数（旧 / 新） | 上层空水位批（旧 / 新） |
| --- | ---: | ---: | ---: | ---: |
| 1 | 386.77 | 654.83 | 608 / 121 | 418 / 68 |
| 2 | 312.05 | 613.86 | 607 / 121 | 434 / 77 |
| 3 | 346.70 | 639.83 | 612 / 121 | 444 / 65 |

| 指标 | 修改前 | 修复后 |
| --- | ---: | ---: |
| TPS 中位数 | 346.70 | 639.83 |
| TPS 范围 | 312.05–386.77 | 613.86–654.83 |
| 平均延时的三轮中位数（秒） | 13.827 | 7.700 |
| P95延时的三轮中位数（秒） | 26.588 | 13.483 |
| 平均业务批大小的三轮均值 | 16.42 | 82.64 |

TPS 中位数提高 84.6%。每轮新版都是121个业务批；稀少参与集合仍受超时和整份请求约束，并非全部达到100笔。此结果来自本机三轮实验，不能作为其他硬件或负载下的固定提升幅度。本轮只对比 Arbor 修改前后，没有重测其他方法的性能排名。

修复后三轮 `network_failures=0`、`view_changes=0`。旧版第一轮 `network_failures=95`，其余旧版轮次为0；第一轮仍全部完成并收敛，各分类 socket/connect/write/timeout/queue/parse/oversized 错误为0。本次未对该旧版计数作单独诊断，没有删除该轮结果。

## 回归与故障处理记录

最终完整 `make test` 退出码0：20个 Python 测试套件共222个测试通过，包含 Arbor 和三个 baseline；C++ 网络、状态摘要检查及新增46项组批/接收缓存逻辑检查通过。新增真实集群检查还验证了交错参与集合的300笔跨片交易完整执行并合成大批。

最初仅修复组批的前后实验中，新版第2轮虽然客户端全部完成，某备用副本却进入孤立换主，收敛失败；原始失败实验保留在 `performance-initial-failed`，未产生聚合成绩，也未纳入上表。追踪发现前序执行尚未完成时，后续提案被直接丢弃。增加有界认证提案接收缓存后，重新从头运行以上六次，全部通过。未放宽收敛条件、改变换主规则或调大超时。

缓存改变了旧多层测试对“丢弃后必须 SYNC”的假设，已更新三个相关测试：错误前沿仍逐项完整拒绝并要求没有投票；每个错误用真实三签 NEW_VIEW 隔离；协调者快照恢复仍必须真正发生；叶子缓存恢复需完整签名日志、执行证明和独立状态重放一致。旧版 SharPer 90/10负载夹具显式加入 `--uniform` 以保留原测试输入；baseline 协议没有修改。

Saguaro、SharPer、AHL 修改前后的预处理源码逐字节一致，修复只生效于 Arbor。执行仍保持原有单批限制，未恢复流水线；客户端 f+1 发送、交易去重、连接复用、网络延时及法定票数保留。
