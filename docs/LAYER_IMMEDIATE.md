# 从低到高逐层立即提交（2026-10-12）

## 当前规则

使用 `config/three_layer_lower_first.json`：m=1、ancestor_streaming=true、ancestor_order=lower_first、低层每Root比例默认1、空块间隔50 ms。仅启用 Arbor 已有流式实现，不改变 C++ 核心或 baseline。

叶子只考虑自身祖先链，每个层级在树中对应一个祖先协调者。该层当前区块的有效 PBFT QC 到齐即可提交，无需先收齐其他祖先同编号区块。按从低到高固定循环；三个协调层时为 `Layer3₁ → Layer2₁ → Layer1₁ → Layer3₂ → Layer2₂ → Layer1₂`。若下一步是 Layer2₁ 且它未到，Layer3₂ 或 Layer1₁ 不能越过它；Root完成后才进入下一轮最低协调层。业务区块分别提交到叶子 PBFT；真实参与方 witness 仍必须收齐才能执行完成。空块/非适用块由有效证明按顺序消费，不计业务 TPS。

Saguaro保留现有NCA 2PC，AHL保留现有两层2PC，SharPer保持现有参与片直接投票及有界调度。没有给baseline加入Arbor策略或本轮优化，全部五个Arbor专有字段在baseline运行配置中删除。

## 验证方式

```bash
python3 -B scripts/benchmark_quick.py --skip-build --budget 300
```

默认lower_first及三个baseline，每种方法先200笔正确性，再1000笔单组性能；状态互相隔离，共享同一原始未签名负载。单case60秒、无完成进展15秒、整体300秒，无故障注入、无重试或万笔性能组。提交日志审计固定低到高顺序、自己的祖先链、不得漏业务块以及所有叶子副本一致。

## Saguaro和SharPer排名变化

找到了用户记忆的历史成绩；它与当前短测的环境、负载长度和输入速率不同：

| 证据 | 环境/负载 | Saguaro TPS | SharPer TPS |
|---|---|---:|---:|
| 10/11 高负载确认第1轮，view=0/network_failures=0 | Mac 8核，10000笔，5000笔/s，请求10笔 | 177.33 | 219.88 |
| 10/11 三轮历史中位数 | 相同环境/负载 | 176.99 | 219.88 |
| 上一轮服务器短测 | Linux 32核，1000笔，1000笔/s，请求10笔 | 510.17 | 368.87 |
| 本轮服务器短测 | Linux 32核，1000笔，1000笔/s，请求10笔 | 488.13 | 353.77 |

10/11与当前Saguaro/SharPer协议文件SHA完全相同，网络实现和增量状态摘要文件SHA也相同。旧baseline配置去掉无作用的Arbor字段后，与当前原始配置完全一致：同9分片、36进程，PBFT上限1000、跨片上限100、等待10/600ms、网络延时和执行负载都未改。历史已使用SharPer FIFO和请求10笔，不能归因为这轮撤掉聚类或请求100→10。

检查上一轮服务器真实提交：Saguaro做了84 INIT、84 DECIDE、180 PREPARE、180 FINISH；尝试1055笔含5次ABORT后重试，实际完成1000笔，每发起批平均12.56笔。SharPer发起60批、1000笔，平均16.67笔；全部参与叶子130批/2100次参与执行。Saguaro较快并不是它合了更大的批，也没有跳过参与叶子共识阶段。客户端TPS按唯一完整交易确认计数，所有参与叶子的实际计数另行核对。

现有并发差异：Saguaro每协调者可保留8个在途2PC批（`baseline/saguaro/protocol.inc:655`）；SharPer每叶子单个未执行跨片槽，新发起受shLocal/shInitiating阻塞（`:556`），收齐每参与片3个执行通知后才释放发起槽（`:478–482`）。Saguaro不同协调者及独立键等待可以重叠，SharPer现有有界调度更受单槽/全参与完成等待影响。 本轮事件日志实测协调者5/6/7在已提交INIT到最终ACK期间同时在途峰值为5/6/2批，确认2PC远端等待确实重叠（不等于纯CPU并行）。这是32核短负载下排名变化的合理机制解释；Saguaro的协议处理量更大，可能在8核长负载中放大处理成本，尚需受控对比验证。

目前能确认测试条件变化与协议并发差异，无法从这些不同条件的样本单独量化核数、输入压力或负载长度各自的贡献。1000笔完成时间约2–3秒的TPS不是稳态容量；现有证据没有显示Saguaro异常加速，不应为恢复预期排名而人为减慢baseline。本轮未进行baseline优化、未再做历史大组测试。
