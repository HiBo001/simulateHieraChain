## 客户端首次投递两个副本

每片 n=4、f=1，首次投递副本 0、1，保证至少一个诚实节点收到。备份将原签名请求转交当前主节点；即使当前主节点为 2、3，仍可处理。客户端仍等待两个不同副本的一致认证回复。超过 500 ms 未确认才扩大到四个副本重试，之后间隔按 1000、2000、4000 ms 退避；所有重试保持原请求和签名。正常 CLIENT 校验也避免在超限检查与普通校验中重复验同一份签名。

## 按变化交易维护去重索引

`pendingTx` 保存交易 ID 对应的内容摘要与请求拥有者；删除请求时只释放属于该请求的交易。`deferredByTx` 保存交易 ID 到等待请求集合的反向索引。提交、跨片完成或所有权释放时记录受影响的交易 ID，只检查相关拥有者及等待请求，完整签名交易列表保持不变。部分重叠、同 ID 不同内容、先到备份的别名仍按现有规则处理。只有安装更高的检查点状态后，重新接纳本地等待请求并全量重建索引。

状态输出新增 `dedup_index_rebuilds`、`dedup_pending_checks`、`dedup_waiter_checks`，便于检查正常路径是否发生了全量索引重建。它们是工程操作计数，不是吞吐指标。

## 增量状态摘要与检查点缓存

新增 `source/state_digest.h`，将顶层对象的每个条目与各标量字段编码为认证叶子。字段标记绑定字段名称及 object/value 类型，长度前缀避免路径歧义。叶子、空树、节点、根使用不同的 SHA-256 域；节点包含自身叶子摘要与左右子树摘要。树按路径排序，用 SHA-256(path) 的确定性优先级形成 treap，因此同一状态不依赖接收或插入顺序。

正常执行显式标记变化条目；一批中多次修改同一条目只处理最终值。修改单条数据的期望工作量为 O(log N)，重复值不重新计算祖先摘要。保留完整 seen、requests、cst_orders 等业务历史，不通过删除去重记录获得性能。快照接收端仍完整重建认证树并验证三份检查点签名，不能仅相信发件人给出的摘要。

检查点生成时同时冻结快照和摘要，收票与重传复用该摘要。完整快照复制、日志写入、远端恢复的全量验证仍有开销。`kv_digest` 保持原 JSON SHA-256，只在 KV 发生变化时重算，所以大 key 空间的 KV 哈希仍是后续可测量的开销。

`state_digest` 的格式改为 `arbor-merkle-v1`，状态输出同时标识算法。编译后应停止旧节点再启动新集群，不能混用新旧二进制或检查点。

## 网络定时等待

未到期消息的正剩余时间向上取整为毫秒，最多等待 10 ms。剩余 0.8 ms 现在等待 1 ms，消除截断成 0 引起的空转。到期消息立即处理，新任务通过原唤醒管道打断等待；发送前比较单调时钟与 due，保持延时下界。实际发送时间仍受操作系统调度影响，可能稍晚于配置时间。

## 多层批次选择缓存（2026-10-03）

叶子选择下一跨片批次时，原实现每次主循环都扫描 `pendingCst`，复制候选证书，再构造和验证祖先前沿。现实现将选择结果保存在本地 `cstSelection`，缓存有结果与暂时无可执行订单两种情况；相关更新路径使缓存失效后才重新计算；重复证明或相同检查点也可能触发保守重建。重建时仍执行原 `validLeafOrder`，候选表仅保存函数调用期间有效的证书指针，缓存本身拥有完整 JSON。

以下路径使缓存失效：新订单插入、`CST_ROUND_CLOSE` 更新待处理证书、祖先轮次证明新增、本片应用推进、检查点安装/恢复以及本片轮次证书更新。缺失祖先证明到达后，无结果缓存也会重新计算。选择缓存不写入共识状态或检查点，不跳过网络消息认证，不改变批内顺序、PBFT 阈值、forward 转发方式或叶子逐批执行规则。

`status.json` 增加 `cst_selection_lookups` 与 `cst_selection_rebuilds`。前者统计查询次数，后者统计实际重建次数；两者差值表示复用次数。它们是本地工程统计，不是 TPS 或协议输入。无需新增配置，重新编译并启动新的 run 后生效；同一已有日志目录内的进程重启仍不受支持。
