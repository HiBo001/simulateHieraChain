# 四种方法统一 100 ms 跨片组批等待

当前默认性能配置统一为 cross_shard_batch_wait_ms=100：Arbor、Saguaro、SharPer、AHL 相同；未使用 Arbor 独立覆盖参数。Arbor 保持低到高 1:1，三个 baseline 的协议代码与处理规则保持原实现。

参数含义：这是跨片业务进入共识前的组批等待上限，满批或遇到各协议原有的分组/容量边界可以提前提交。它不是所有分片每个 PBFT 阶段都必须等待的时间，也不是固定出块周期。普通 batch_wait_ms 仍为 10，view_timeout_ms 仍为 2000，cross_shard_batch_size 仍为 100，batch_size 仍为 1000。

| 方法 | 100 ms 参数的主要使用位置 |
|---|---|
| Arbor | Root/Child 协调者的跨片业务组；按该参与集合最早请求的入队时间计算 |
| Saguaro | NCA 协调者发起不足额 INIT 批次；DECIDE 和叶子 PREPARE/FINISH 不重新等待 100 ms |
| SharPer | 发起叶子的可继续增长且不足额跨片 FIFO 前缀；关闭前缀及参与节点已有批次走原规则 |
| AHL | 唯一上层协调者的 INIT 组批，保留原两层 2PC 处理 |

统一数值控制了参数差异；各协议的计时起点、提前提交条件及消息/共识阶段仍按原实现，不能解释为四种方法具有完全相同的组批机制。

在 10.1.101.71（32 vCPU）复用同一套已编译程序，发送速率 5000 笔/秒，seed=42，每个客户端请求最多 10 笔。各方法先运行一次 200 笔正确性，再运行一次 1000 笔性能；各运行状态、密钥、端口、run id 独立，串行执行，无故障注入或重试。

负载为 100% 跨叶子分片：95% 在同一 Child 子树内、5% 跨 Child 子树，10% 为三个参与分片。四种方法使用同一 unsigned 业务及请求顺序，按自身协议路由；Arbor/Saguaro/SharPer 为九分片、六叶子、每片四副本，AHL 保持两层七分片、同六叶子、每片四副本。相同交易执行与网络成本通过现有比较校验。

8 个真实运行全部 PASS，整组耗时 49.03 秒；85 项配置、runner、成本比较及异常终止检查通过，耗时 5.778 秒。客户端完成全部交易，无重复、仅排序、客户端错误、业务消息失败或换主；副本摘要收敛，Arbor 24 个叶子副本顺序审计通过，零双块合并。测试节点已清理。

网络计数另行记录：AHL 上层副本 0 在客户端完成快照与排空后均有 1 次 network_connect_errors，network_failures 为 0，其余网络错误及换主计数为 0。守卫在客户端活动阶段未触发传输错误；源码的空连接 POLLERR 也会增加该连接计数，快照不能确定目的端和精确发生时刻。该情况可能来自连接关闭，无业务消息失败证据，保留原始计数且未重跑。

| 方法 | 跨片等待 ms | TPS | 完成时间 s | 平均延迟 ms | P95 ms | P99 ms |
|---|---:|---:|---:|---:|---:|---:|
| Arbor 1:1 | 100 | 1279.87 | 0.781 | 390.81 | 586.99 | 610.08 |
| saguaro | 100 | 746.80 | 1.339 | 572.00 | 1069.49 | 1219.03 |
| sharper | 100 | 429.74 | 2.327 | 938.92 | 1837.90 | 2035.68 |
| ahl | 100 | 320.71 | 3.118 | 1454.79 | 2718.35 | 2954.32 |

统一参数下，Arbor 对 Saguaro、SharPer、AHL 的 TPS 分别为 **1.71、2.98、3.99 倍**。TPS=1000/客户端发送开始至全部执行确认完成的时间，包含发送及执行确认等待；本结果是一次短测，不是稳定容量结论。

此前只把 Arbor 设为 100 ms、基线保留 600 ms 的倍率混入了组批参数差异。今后的当前配置性能比较以本次全部 100 ms 结果为准。

下面复用上一轮同二进制、同输入、同发送速率的全部 600 ms 对照，用于查看参数变化的方向；两轮时间不同且每方法只有一次样本，不能将差值全部视为精确的参数因果效应。

| 方法 | 上轮全部 600 ms TPS | 本轮全部 100 ms TPS | 变化 |
|---|---:|---:|---:|
| arbor | 799.48 | 1279.87 | +60.09% |
| saguaro | 547.80 | 746.80 | +36.33% |
| sharper | 362.49 | 429.74 | +18.55% |
| ahl | 294.61 | 320.71 | +8.86% |

所有方法均完成更快，但基线平均延迟并非一致下降：例如 Saguaro 和 AHL 的平均延迟比上一轮略高。TPS 的分母是最后完成时间，提前释放尾部小批次能缩短完成尾部，同时不同组批形态和协议排队仍可能影响其他交易的延迟，不能只用 TPS 概括全部性能。

| Arbor 每个叶子主节点的累计时间均值（客户端结束时） | 毫秒 |
|---|---:|
| 等待 Root | 1.11 |
| 等待 Child | 2.66 |
| 等待 execution witness | 439.48 |
| 等待叶子 PBFT 槽 | 151.39 |
| 调度处理 | 71.07 |
| 事务计算 | 20.84 |

Root/Child 等待均很少，主要剩余等待为 execution witness 与叶子 PBFT。事务计算约 21 ms/叶子。上述是墙钟累计均值，不是 CPU 时间；等待与处理范围存在重叠，不能相加作全局耗时占比。

修改了三个当前性能输入配置：config/three_layer_lower_first.json、config/three_layer_locality.json、config/ahl_two_layer_locality.json。原始 600 ms 文件按同名 _wait600.json 保存，只有等待字段与当前配置不同。代码、网络参数、请求批次和协议阶段未改动；历史结果仍保留。

复现当前公平比较，无需 Arbor 专用覆盖：

```bash
cd /root/tanghaibo/simulateHieraChain
python3 -B scripts/benchmark_quick.py --skip-build --rate 5000 \
  --correctness-count 200 --count 1000 --batch 10 --seed 42 --budget 180
```

默认仅运行 Arbor 1:1 和三个 baseline。单项上限 60 秒、无完成进展 15 秒、预留清理预算；异常立即停止后续且不重试。改变参数需新的正确性报告，不能直接复用不同配置的 200 笔结果。本轮未启动 10000 笔正式测试。

历史全部 600 ms 对照需要同时指定：

```bash
python3 -B scripts/benchmark_quick.py --skip-build --rate 5000 \
  --config config/three_layer_lower_first_wait600.json \
  --ahl-config config/ahl_two_layer_locality_wait600.json --budget 180
```
